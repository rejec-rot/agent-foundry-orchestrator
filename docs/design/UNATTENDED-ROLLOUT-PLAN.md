# 无人值守交付计划

状态：准备工作已启动；尚未部署、未启用 live、未授权新外发。
计划基线：`c66617a`；依赖已冻结的 A1a 设计及其 H1–H3。

## 范围与顺序

优先完成无人值守的必要基础；静态 HTML 和新的任务提交能力不作为本轮前置。
任务执行、通知投递、边界恢复保留独立的状态、调度职责与结果。
本计划不是对现有系统通过无人值守生产验收的声明。

| 批次 | 交付 | 放行条件 |
|---|---|---|
| U0 可观测收尾 | CLI 当前任务证据与资产历史分区；明确 recovery ID 不再回退附加其它 ID；终端输出控制字符安全显示 | 专项回归，无写入、无网络；关联不串任务 |
| U1 安全基础 | 持久化保护 epoch、预期保护元数据；生命周期/人工恢复/A1a 共享资产锁协议 | 活着的持有者不被 TTL 抢占；锁覆盖真实修改；重叠检测与登记互斥 |
| U2 恢复事务 ✅ | 修改前持久化门、三分类核对；释放、复验、RESULT、任务落盘、告警关闭依次完成 | 各阶段故障注入；已修改或未知转人工，不重复释放；结果按持久化阶段判定 |
| U3 A1a dry-run ✅ | 白名单、资格解释、epoch 预算、退避、耗尽及人工待办 | 默认 off；dry-run 不改权限、任务及告警；状态损坏拒绝而非当作空队列 |
| U4 部署准备 ✅ | 独立通知与恢复调度单元模板、私密配置说明、状态查询、停止与重启流程 | 仅提供未启用模板；不复制真实凭据、不安装或启动服务；两类调度互不冒充成功 |
| U5 授权试运行（仅 dry-run）✅ | 专用白名单资产、小批任务、人工观察窗口 | 用户确认资产、执行器、网络、资源/时间/调用上限、通知目的地及允许操作；每项授权有记录 |
| U6 生产验收 | 固定版本的真实成功、拒绝、超时、重启、保留恢复和依赖故障路径 | 无误提升、无越权解锁、异常可见、残留可核对；备份恢复与停用流程实测 |

## 不可放宽的边界

- A1a 默认关闭，白名单默认空。共享锁与 epoch 未落地之前不得 live。
- 无自动 force、存活写者确认绕过或猜测权限恢复。
- RESTORE_INCOMPLETE、修改阶段无法确认、审计不完整均不得自动再次释放。
- 仅 INTENT 不自动等同于未修改；必须满足冻结设计 H1 的证据条件。
- 通知成功不是任务或恢复成功；通知失败不得隐藏，且不得阻断独立恢复资格判断。
- 人工未决任务不自动推进；首次上线不扩展跨主机互斥或无限制任务提交。
- 旧的模型调用或飞书测试授权不自动继承到本计划。

## 验证与交付节奏

每批：实现与负向用例一起交付 → 专项 → 一次全量 → 固定版本与限制清单。
不因一般体验问题增加设计轮次。安全、证据正确性、数据损坏及越权问题仍是放行阻断。
未实现的机制不能用文档守卫通过代替行为验收。

**进度**：U0–U5 已交付并复核；**U6 第一批 + 第二批（本地故障矩阵）完成**：G1/G2 30/30、H1–H4 21/21，均连续 3 次稳定、无残留。**未覆盖**：ENOSPC（本机无满卷、无特权挂载，不可忠实注入；最接近的写失败 EACCES 已由 G1-3 覆盖）、**A1a「live 尝试→写入→重启→再读取」闭环**（H4 只验读取侧续查）、真实模型任务（A1 范围外）。
**U2 已知差异（如实记录，非阻断）**：`recoverRetainedBoundary()` 的 `persistTask` 是**调用方钩子**——A1a 必须传入（未传则事务只走到 RESULT 与告警关闭，不校验任务落盘）；`af-admin boundary recover` 人工路径不传该钩子，因为该操作可能不对应任何任务记录。因此「任务落盘并重读」这一成功条件在**人工路径**下不适用，**A1a 路径必须适用**。
