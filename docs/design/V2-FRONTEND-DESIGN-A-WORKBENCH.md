# V2 前端设计书 A：任务工作台方向（密度优先的专业工具）

状态：**设计评审稿（未实现，不改变任何行为）**。编制日期：2026-09-30。
定位：三份候选前端设计方向之一（另见 `V2-FRONTEND-DESIGN-B-PIPELINE.md`、`V2-FRONTEND-DESIGN-C-GALAXY.md`）。
三份覆盖**同一套功能基线**（§2），差别只在信息组织方式与视觉语言；最终只选一个方向实施。

---

## 1. 设计方向

| 项 | 内容 |
|---|---|
| 核心创意 | **证据驱动的专业工作台**：一屏回答三个问题——任务到哪一步了？凭什么（证据）？我现在能做什么（真实能力）？ |
| 气质参考 | Linear 的列表效率 + 代码编辑器的多面板 + 终端仪表盘的诚实感；不炫技，追求密度与可追溯 |
| 适合场景 | 日常高频使用、异常排查、审计追溯；是三份方案中**实施成本最低、信息效率最高**的方向 |
| 字体声明 | 标题/数字：**Space Grotesk**（可变字重 300–700）；数据/ID/哈希/状态码：**IBM Plex Mono**；中文正文：思源黑体。字号跳跃 ≥3 倍（14px 正文 / 48px 页首） |
| 色彩 | 深墨绿底 `#0d1512`；主文字 `#e8ede9`；强调色琥珀 `#ffb224`（仅用于当前阶段与待人工项）；状态色语义化：进行中青、通过绿、失败红、不可核验灰。**禁止紫/靛蓝渐变、白底、统一圆角** |

## 2. 功能覆盖基线（F1–F12，三份设计书共用）

| # | 功能 | 本方案落点 |
|---|---|---|
| F1 | 创建 V2 任务（选项目、目标、允许范围、显式独立 author/reviewer） | 创建向导（三步，左栏入口） |
| F2 | 阶段进度可视化（编写→评审→门禁→验收→提升） | 详情页顶部**阶段条**（文字+图标+颜色，**无百分比**） |
| F3 | 看见 worker 之间的任务、工作细分与执行身份 | 详情页中栏「执行者分工」面板（单作者多工作者：作者下的 worker 列表，各自身份/分工/最近活动） |
| F4 | 实时状态更新 | SSE/轮询，每区块带 `as_of`；断线显示最后更新时间 |
| F5 | 直接给主作者下指令、调整工作 | 作者面板内「注入指令」输入框（经 `operator-control`；状态分**排队/已接收/已落实**三档，各有独立证据） |
| F6 | 修改 worker 的细分工作内容与方向 | worker 行内「调整分工」入口（同 F5 通道，标注注入边界：不打断运行中进程，不承诺即时生效） |
| F7 | 密封候选差异 + 评审/验收/提升证据 | 右栏上下文区：manifest 差异树、证据卡（含证据身份与有效性，日志摘要≠完整日志） |
| F8 | 异常处理与恢复（恢复计划、取消、崩溃恢复） | 「异常中心」页 + 详情页操作菜单（恢复先算计划、锁内复核、409 过期提示） |
| F9 | 人工闸门 WAITING_HUMAN | 阶段条琥珀色停靠态 + 待决项列表；**批准仅 CLI 签名**，页面只引导不代办 |
| F10 | 能力分级诚实展示（未接通不开放、读不到=不可核验） | 全局规则：未接通功能不渲染入口（不是置灰）；`unverifiable` 显式标注 |
| F11 | 只读/写模式边界 | 页顶模式徽标；写操作需 `--allow-write` + 操作令牌；**浏览器不持有审批密钥**（声明放页尾） |
| F12 | 中文界面、桌面优先、键盘可达、reduced-motion | 全站中文；全操作可键盘完成；`prefers-reduced-motion` 关闭全部动效 |

**导航规则**：任意 ID/路径可双向跳转（任务 ↔ 告警 ↔ 恢复 ↔ 提交 OID），与只读控制台一致。

## 4. 关键交互

1. **创建向导**（F1）：选已注册项目 → 填目标与允许修改范围 → 显式选 author + 独立 reviewer → 预检（强 writer scope、验收 profile 缺失即阻塞，不默认降级）→ 幂等提交（重复点击/刷新不产生第二任务）。
2. **注入指令**（F5/F6）：选中作者或某 worker → 输入指令 → 服务端校验目标与边界 → 返回注入记录 ID → 该指令行显示三档状态（排队/已接收/已落实），每档独立证据；**未落实不显示"已生效"**。
3. **恢复**（F8）：操作菜单 → 服务端只读计算恢复计划 → 展示计划内容与影响 → 确认执行（带 `expected_state_version`，过期返回 409 并强制刷新）。
4. **人工闸门**（F9）：`WAITING_HUMAN` 时阶段条停为琥珀色，右栏列出待决路径；页面给出 CLI 命令提示（`af-admin v2 gate-resume --task <id> --reason <why> --confirm`），**无"批准"按钮**。

## 5. 视觉与动效

- 一次编排式页面加载：左栏→中栏→右栏错峰揭示（animation-delay 120ms 步进）；**禁止 loading spinner**，数据未到显示骨架行+`读取中`文字。
- 状态变化用颜色+文字过渡（200ms），失败项左侧 2px 红色实线描边；不用脉冲/呼吸灯。
- 背景：深墨绿底上叠加极淡噪点纹理与单色网格线（工程感），不用纯色死底。
- hover 只增强不削弱；焦点环 2px 琥珀色（键盘可达可见）。

## 6. 技术方案

- 延续 `server/read-api.mjs` + `web/` 的无构建路线：原生 ES modules + 少量 Web Components；SSE 推送，断线降级 5s 轮询并标 `stale`。
- 差异树虚拟滚动（万级文件）；日志按不可信文本转义渲染；**候选脚本绝不在控制面同源执行**。
- 所有查询走纯读取入口（`readTaskFile`/`readBoundaryAlertEvents`+内存重放），前端不触发任何带副作用的 getter。

## 7. 与后端契约对齐

- 单一写者：前端不保存另一套任务状态，生命周期真源是任务文件；事件只是投影，缺口如实标注。
- 写接口全部带幂等键 + `expected_state_version`；400/403/404/422/503 按既定语义映射到可读提示。
- 遵守 `SYSTEM-ARCHITECTURE-NEXT.md` §6 统一行为：`missing`/`unverifiable`/`stale`/`conflict` 各有明确样式，**读不到绝不渲染成"正常"**。

## 8. 验收标准（方向特有，通用部分沿用 V2-FRONTEND-PLAN §9）

- 单屏（1440×900）内无需滚动可见：当前阶段、author/reviewer 状态、最近证据、可用动作。
- 键盘从任务列表到「注入指令」提交完成全程无鼠标。
- 断网 10s 后页面显示最后更新时间与 `stale`，恢复后自动续传且不重放旧动作。

## 9. 取舍与风险

- 优点：实施最快（复用现役 `web/` 最多）、信息效率最高、无障碍最容易做全。
- 代价：视觉惊喜度最低，不满足"像星球一样"的直觉化表达愿望。
- 风险：密度过高导致新用户看不懂——用「阶段条 + 一句话现状摘要」兜底。
