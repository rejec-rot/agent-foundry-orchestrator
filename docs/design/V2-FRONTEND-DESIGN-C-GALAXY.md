# V2 前端设计书 C：星系方向（three.js 沉浸式，重做版）

状态：**设计评审稿（未实现，不改变任何行为）**。编制日期：2026-09-30。
定位：三份候选前端设计方向之一（另见 `V2-FRONTEND-DESIGN-A-WORKBENCH.md`、`V2-FRONTEND-DESIGN-B-PIPELINE.md`）。
三份覆盖**同一套功能基线 F1–F12**（定义见 A 档 §2，本档 §3 只写映射差异）。

> **前次教训（2026-09-24 ~ 09-29 星图/星球方案被取消的原因）**：未设计先行、堆随机星域、
> 把地球放核心、改动后自己不截图验证。本档是**重做版**，先把设计定死再谈实现，
> 并明确 3D 不可用时的一等公民 2D 回退（§6）。

## 1. 设计方向

| 项 | 内容 |
|---|---|
| 核心创意 | **一个任务 = 一个恒星系，且只有这一个硬创意**。恒星 = 任务目标（唯一引力中心，**不是地球、不拟物**）；行星 = 六个阶段（编写/评审/门禁/验收/提升按流程顺序排布轨道）；卫星 = worker（围绕其所属阶段行星运行）。系统状态 = 空间状态：当前阶段行星被彗尾光锥照亮，待人工行星琥珀色脉动，失败行星出现红色环带裂缝 |
| 为什么成立 | V2 是"单作者但不是单工作者"：一个编写阶段行星挂多颗 worker 卫星，恰好回答了"多个编写工作同时进行怎么办"——**卫星群就是答案，不需要多个星球** |
| 气质参考 | awwwards 级 3D 站点（parallel-universe / james-murray-3d-portfolio）的相机叙事，但信息可读性永远优先于氛围 |
| 字体声明 | 标题/数字：**Unbounded**（300/800 两极）；数据：**IBM Plex Mono**；中文正文：思源黑体。HUD 文字全部为 DOM 渲染（不参与 3D 变换，保证清晰与可选中） |
| 色彩 | 深空 `#04060e`；恒星暖白 `#fff3d6`；主色冷青 `#7de3ff`；强调彗星橙 `#ff6b35`（当前阶段/待人工）；失败红 `#ff3b4e`。星光为点缀不是主照明。**禁止紫/靛蓝渐变、禁止随机彩色星云贴图** |

## 2. 与已取消方案的关键差异

| 维度 | 已取消方案 | 本档 |
|---|---|---|
| 设计流程 | 边做边改，先实现后看效果 | **设计先行**：本档评审通过后才动工；先做静态 2D 稿（Figma 级描述+单帧渲染图）确认构图 |
| 场景内容 | 随机星域背景、地球为核心 | 场景内**每个元素都必须绑定真实数据**（§7 硬规则）；无数据绑定的装饰粒子总数 ≤300 且仅作远景深度暗示 |
| 信息承载 | 好看但读不出任务状态 | 状态优先级：HUD 面板（DOM，完整信息）> 行星标注（阶段名+状态词）> 3D 形态（氛围层） |
| 验证方式 | 未自查截图 | 每次改动必须真实浏览器截图对比（沿用工作方式要求） |

## 3. 功能覆盖（F1–F12 映射）

| # | 功能 | 星系方向落点 |
|---|---|---|
| F1 | 创建任务 | 场景外独立页面（创建是表单任务，不硬塞进 3D）；创建成功后相机飞入新星系 |
| F2 | 阶段进度 | 行星按流程顺序分布于递增轨道；已完成的行星沉入内侧轨道并固化，当前行星居视觉焦点；**无百分比** |
| F3 | worker 可见性 | 卫星围绕阶段行星：大小=分工粒度（仅相对示意，不虚构数值）、标注=身份与分工标题、闪烁=最近活动 |
| F4 | 实时更新 | SSE 驱动；状态变化 = 行星材质/光照过渡（500ms）+ HUD 同步；相机不自动乱动（只在阶段迁移时缓动推进一次） |
| F5 | 给主作者下指令 | 点击恒星（任务核心/主作者）→ HUD 指令面板；恒星是主作者的自然隐喻 |
| F6 | 调整 worker 分工 | 点击卫星 → HUD 显示该 worker 详情 + 指令面板（目标锁定该 worker）；注入记录作为卫星旁的信标光点，三档状态（排队/已接收/已落实） |
| F7 | 差异与证据 | 点击评审/验收/提升行星 → HUD 抽屉（差异树、证据卡、提交 OID）；**3D 场景不承担长文阅读，全部交给 DOM 面板** |
| F8 | 异常与恢复 | 失败行星红色环带 + HUD 恢复计划面板（同 A/B 的服务端契约）；恢复成功后环带愈合动画 |
| F9 | 人工闸门 | 门禁行星琥珀脉动 + 待决项 HUD 列表 + CLI 命令提示；无批准按钮 |
| F10 | 能力分级 | 未接通能力**不存在对应天体**；数据 `unverifiable` 的天体变为灰白线框 + 问号标注 |
| F11 | 只读/写边界 | HUD 顶栏模式徽标；页尾密钥声明；写操作仅经操作令牌通道 |
| F12 | 可访问性 | **2D 回退视图（§6）为一等公民**：默认在 `prefers-reduced-motion`、WebGL 缺失、或用户切换时启用；键盘通过 2D 视图完成全部操作（3D 场景本身不做键盘遍历承诺） |

## 4. 信息架构

```text
┌──────────────────────────────────────────────────────┐
│ HUD 顶栏：任务选择 · 模式徽标 · as_of · 2D/3D 切换      │
├──────────────────────────────────────────────────────┤
│                                                      │
│        ✦ 恒星（任务目标/主作者）                        │
│      行星1 编写 ── 卫星 w1 w2 w3（worker）             │
│      行星2 评审 ── 卫星 reviewer                       │
│      行星3 门禁 · 行星4 验收 · 行星5 提升               │
│      （当前阶段行星带彗尾光锥，居视觉焦点）               │
│                                                      │
│   右侧 HUD 抽屉（DOM）：差异/证据/指令/恢复/待决项       │
├──────────────────────────────────────────────────────┤
│ HUD 底栏：一句话现状摘要 · 页尾密钥声明                  │
└──────────────────────────────────────────────────────┘
```

页面：星系主视图（默认）、2D 回退视图（信息等价）、创建页、异常中心（复用表格视图）、执行器与环境。
**不做多星系并列星图**：首版单任务单星系，任务切换经顶栏选择器（多星系场景留待评审，避免重蹈"星域堆砌"）。

## 5. 相机与动效叙事

- **一次编排入场**：黑场 → 恒星点亮 → 行星沿轨道依次入场（120ms 错峰）→ HUD 滑入。只演一次。
- 相机三段式：全景（看懂全局）→ 选中行星推近（看 worker 卫星）→ 打开 HUD 时相机定住（读信息时画面不抢戏）。
- 轨道运动极慢（周期 ≥90s）且 reduced-motion 下全静止；**流畅和干净就是技术：锁定 60fps，掉帧优先砍粒子再砍光晕**。

## 6. 技术方案与 2D 回退

- three.js：行星用 InstancedMesh + 自定义 shader（单 fragment shader 提供氛围，投入产出比最高）；后处理仅 Bloom 一档，可关。
- 数据层与 A/B 共用 read-api/SSE；3D 场景只是投影层，**状态机只有一份**（与 B 档同一 reducer 设计）。
- **2D 回退**：同一数据层渲染为 SVG 同心轨道图（结构同 B 档管线但按轨道布局），DOM 交互、完整键盘可达；不是"降级版"而是并行的正式视图。
- 性能预算：总 drawcall ≤50，粒子 ≤300，纹理 ≤4 张 1K；不达标不上线。

## 7. 与后端契约对齐

同 A 档 §7，另加星系特有硬规则：
1. **场景元素零虚构**：任何天体必须能指出它投影自哪条权威记录；投影关系写在 HUD「此天体是什么」里。
2. 无数据 = 线框灰白天体 + `unverifiable` 标注，**绝不亮着假装正常**。
3. 前端不推算进度：没有"轨道位置=完成度"的映射，位置只表达流程顺序。

## 8. 验收标准（方向特有）

- 单帧静态截图（无动画）即可看懂：当前阶段、worker 分布、异常位置。
- 2D 回退视图与 3D 视图信息逐项等价，且 2D 下全部功能可键盘完成。
- 60fps（M 系列核显 / 中端独显各测一次）；`prefers-reduced-motion` 下无自动运动。
- 随机抽 3 个天体点击，HUD 都能给出其权威来源记录引用。

## 9. 取舍与风险

- 优点：最贴合"像星球一样"的原始愿望；演示与情感冲击力最强；worker 卫星群天然表达"单作者多工作者"。
- 代价：实施成本最高（约为 A 档 2–3 倍）；可读性需要 HUD/2D 视图双重兜底。
- 最大风险：再次滑向"好看但读不出信息"。**熔断条款**：若静态单帧截图测试（§8 第 1 条）两轮不通过，回退到 B 档管线方向实施，3D 仅保留为可选皮肤。
