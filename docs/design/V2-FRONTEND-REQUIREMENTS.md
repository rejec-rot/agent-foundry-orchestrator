用途：作为后续前端设计/实现的原始依据。本文只收录"你要什么"，不含任何设计结论；星图/星球等已取消设计的细节不复述为新要求。

## 一、核心目标（跨会话反复出现）

1. 直观可视化：把任务进度/流程直观表现出来（"星系或者一个流程图"；"每个阶段是个星球"）。
2. 看得见谁在干什么：能看 worker 之间的任务、工作细分与执行身份。
3. 实时性：画面随进程变化更新状态（"我们的目标是什么，且这张图会随着进程的变化而更新状态"）。
4. 可操作：可以直接给主作者下指令、调整工作；能修改 worker 细分化的工作内容和方向。
5. 贴合真实系统：依据 V2 系统真实文件与 README 设计，不凭空发挥。

## 三、你确认过的计划书中的功能要求（2026-09-20《V2 系统前端建设计划书》，web/ 已按此交付）

- 定位：Trusted Import V2 任务工作台 —— 创建任务、独立 author/reviewer、查看密封候选差异与验收证据、确认提升结果、处理有明确恢复方案的异常。
- 只展示真实能力：能力分级；未接通的功能不开放；不用 mock 截图当作联调证据。
- 生命周期真源是任务文件；前端不保存另一套状态；事件只是投影，缺口如实标注。
- 浏览器不持有审批密钥；恢复 / 批准 / 提升仅经 CLI 签名执行；界面不扩大写入权限，不改动 canonical 的唯一提升路径。
- 展示口径：不显示无依据的百分比进度、剩余时间、token 或费用；状态用文字＋图标＋颜色；中文界面；桌面优先、键盘可达。

## 四、工作方式要求

- 改前端必须用真实浏览器验证：开始本地服务、驱动浏览器、截图对比；"你自己没有截图观看有没有改变吗？"
- 页面必须真的能打开、可用。
- 美学基线：更美观、现代；学习获奖站点手法；规避"AI 常见丑法"。
