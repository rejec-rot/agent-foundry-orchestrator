# 0003 — 上游许可未解决：本仓库保持 UNLICENSED 且不得公开

- 状态：**已采纳**（阻塞项，待维护者提供授权信息后重新评估）
- 日期：2026-09-16
- 决策者：本仓库维护者

## 背景

复制上游代码前做的事实核查：

| 检查 | 结果 |
|---|---|
| 上游 `LICENSE` / `LICENSE.md` / `COPYING` | **不存在**（实测 `ls LICENSE*` 无结果） |
| 上游 `package.json` | `"private": true`，**无 `license` 字段** |
| 上游是否在 README 声明许可 | 无许可声明 |

法律后果：**无许可 = 保留所有权利（All rights reserved）**。上游没有授予复制、修改或再分发的许可。
本仓库是它的**派生作品**（derivative work），因此默认不得公开分发。

## 决策

1. 本仓库 `package.json` 显式声明 `"license": "UNLICENSED"` 且 `"private": true`
2. **不添加任何开源许可文件**（在获得授权前，添加许可等于代替原作者授权）
3. 在 `NOTICE.md` 中完整记录来源、改动与许可状态
4. 本仓库**仅作为本机私有分支**存在，**不得推送到公开仓库**

## 备选与为什么不选

| 备选 | 排除理由 |
|---|---|
| 直接加 MIT/Apache-2.0 | 我无权代替原作者授权。若维护者不是作者，这会造成许可欺诈 |
| 直接推公开仓库 | 同上，且公开后再撤回已产生的副本不可行 |
| 删除 `NOTICE.md` 保持"干净" | 掩盖来源会同时掩盖许可风险，是最差选项 |
| 不复制代码，只保留文档与设计 | **这是许可无法解决时的可行路径**（见下） |

## 若维护者不是作者、且拿不到授权

版权保护的是**这段具体代码**，不保护**思想与方法**。因此可行路径是：

- 保留 `docs/`（路线图、模块图、设计资产说明）——这些是本会话产出的分析，不是上游代码
- 代码部分按 `docs/MODULE-MAP.md` **用成熟组件重新拼装**（P1–P6 本来就是"用现成组件替换手写件"，
  方向与"独立重写"一致）
- 只把 `docs/PRESERVE.md` 的两个**设计性质**作为规格重新实现，不复制其实现细节

此时本仓库可另起一个干净的初始提交，并按维护者意愿选择许可。

## 需要维护者回答的问题

1. 你是否是上游作者（`opperl1114`）？
2. 若不是，是否持有作者的授权（书面/邮件/issue 均可）？
3. 本仓库的用途是：本机学习 / 自用 / 将来公开 / 商业？

## 后果

- 正面：不会在来源不明的派生代码上附加错误许可；许可问题被显式记录而非掩盖
- 负面：**在得到答复前，本仓库无法公开发布**；若将来要公开，可能需要一次"代码重写"而不是"复制+修改"

## 验证方式

- `package.json` 中 `license` 为 `UNLICENSED`
- 仓库内不存在 `LICENSE` / `LICENSE.md` / `COPYING` 文件
- 仓库未配置任何远程地址（`git remote -v` 为空）
