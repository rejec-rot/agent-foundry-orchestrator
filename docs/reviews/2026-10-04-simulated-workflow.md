## 如何重跑

```bash
node qa/simulated-workflow.mjs --serve --port 8788
```

需要 Chromium；可通过 `AF_BROWSER_BIN` 指定程序。端口被占用时选择另一端口，自动测试可以使用 `--port 0`。可选 `--output-dir` 指向新目录，已有报告不会覆盖。省略 `--serve` 会生成报告后退出。Ctrl+C 停止服务，保留演示数据和报告。

## 演示实际经过的流程

| 阶段 | 行为和证据 |
|---|---|
| 1 商讨 | 操作员与 Planner 对话，没有 Worker 提前执行 |
| 2 提案 | 三项任务，A/B 并行，C 依赖二者；等待人工确认 |
| 3 派工 | 三位 Worker 使用两个虚拟执行器和三个模型/思考强度配置 |
| 4 改向 | 执行中调整 A；旧尝试被拒绝，A/C 挂起，B 成果保留 |
| 5 重派与整合 | Planner 下达输入校验新方向；A 版本 2，B 版本 1，生成整合候选 |
| 6 首轮复检 | Reviewer 沿用 Planner 模型与 high 强度，使用独立会话 |
| 7 局部返工 | Reviewer 返回 NEEDS_FIX：C 写死了 3；Planner 只选择 C 返工 |
| 8 再次复检 | C 改为导入 A/B 计算；A/B 成果保留，第二个独立会话复检 |
| 9 交付 | PASS 后实际运行两项 Node 测试，临时 Git 仓库的正式引用晋升 |

最终文件是 `src/a.mjs`、`src/b.mjs`、`src/c.mjs`。验收实际检查结果为 3，以及合法输入返回原值、Infinity/NaN 抛出 TypeError。

## 模拟边界

起始目标与项目由 fixture 预置，演示指令通过既有持久化命令入口提交，网页提供只读回放。Agent 回复、模型目录、思考强度能力和执行范围退出证明均由受控测试适配器提供。演示不会调用真实模型或发现本机 Agent；不能据此声称真实模型质量或真实 OS 隔离通过验证。

团队控制器、消息回执、版本围栏、成果快照、Trusted Import、Node 验收和临时仓库的 Git 引用更新实际执行。使用现有测试 fixtures 和控制器，不引入另一套调度器或生产执行器注册表。网页只读，所有非 GET/HEAD 请求拒绝；虚拟模型配置不会进入真实项目。原有 8787 实例复查仍为零团队、零任务。

## 演示发现并修复的问题

交付页此前保留任务书签却未自动选中任务。现在直接访问书签、旧入口跳转、改变书签和重载会显示对应详情，手动选中也更新地址。畸形编码与路径型书签不查询任务；请求版本保护阻止 A → B → A 的旧响应覆盖当前详情、事件和消息。

阶段条此前没有读取 `trusted_import.phase`，也未对应 `PROJECTED`、`AUTHOR_RUNNING` 和 `PROMOTED`。现在使用真实阶段数据，评审时标记当前阶段，完成后八阶段均标记完成。阶段截图分别验证两次 REVIEW 和最终 PROMOTED。

失败报告保留已完成阶段、通过检查和失败原因。SIGTERM/SIGINT 更新中断状态并清理自己的浏览器；独立中断验证确认 `running:false`、`interrupted:true` 且没有子进程残留。
