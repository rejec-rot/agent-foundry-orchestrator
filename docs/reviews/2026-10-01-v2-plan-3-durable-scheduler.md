# 处理方案三：持久调度与事务状态存储

日期：2026-10-01。依据：[复检报告](2026-10-01-v2-backend-recheck.md)。状态：处理方案，尚未实施。

目标是把启动请求、提交身份、任务状态、执行归属、执行器容量和审批记录集中到事务状态存储，由常驻调度服务管理 worker。存储产品和部署拓扑需要在本方案选定后进一步确认；本文件不预定具体数据库、依赖或工期。

## 最终职责

Web/CLI 写入带幂等身份的持久操作请求；调度服务原子领取操作并分配执行容量；worker 以带 token 的执行身份推进现有 V2 workflow，通过状态接口报告结果。重启后按持久请求、租约和 writer 停止证据恢复调度。

任务/提交/熔断的权威状态放在事务存储中。JSON 文件如继续提供给控制台或兼容工具，只作投影和导出；授权、启动和恢复不得依赖可能滞后的投影。避免同时维护两份可写真相。

## 九项问题如何处理

| 问题 | 处理方式 |
| --- | --- |
| Q1 | 执行器槽位、启动节流、熔断在事务中校验和修改；所有 worker 从同一状态来源取得运行许可 |
| Q2 | 任务执行归属使用原子 claim、租约和 token，停止将初始化中的文件作为归属凭据 |
| Q3 | 创建与恢复是不同操作；task ID 不重复创建，状态版本和终态由受控状态更新维护 |
| Q9 | 审批证据与候选内容绑定；审批完成生成可领取的恢复操作，新 worker 验证并取得可信审批 |
| Q4 | 提交账本由统一存储接口访问，cwd 不参与其身份或位置 |
| Q5 | checkpoint 创建/反馈成为受控操作；worker/CLI 使用任务身份访问同一状态来源 |
| Q6 | 幂等 key 唯一身份、task 绑定与删除条件在同一事务中验证 |
| Q7 | claim/fix 时检查最终执行器及原会话，不允许在取得许可后切换到未经检查的执行器 |
| Q8 | 每次 reviewer 结果仍统一做取消、独立性和绑定检查，不能因存储事务化而省略 |

事务本身不会终止外部 writer。仍要保留运行 scope、心跳、失锁停止以及停止确认；归属失效不等于可立即重试或再次写入。重启恢复也不能简单把 RUNNING 重置成 CREATED。

## 实施步骤

1. **先建立安全基线**：为九项问题建立预期行为回归；在迁移准备阶段先修当前生产路径的 P1。若系统仍在持续使用，应补齐其余五项补丁，不能长期保留已知错误等待新架构。
2. **定义持久模型与操作接口**：覆盖任务、提交、操作请求、执行租约、执行器槽位、熔断、审批、checkpoint 和必要审计证据，明确唯一身份及状态更新条件。
3. **实现调度链**：请求持久化 → claim → 分配容量 → 启动 worker → 心跳/报告 → 结果确认；处理启动失败、重复请求、服务重启和 worker 失联。
4. **适配业务入口**：Web/CLI/旧兼容入口使用同一操作接口；保留 V2 Trusted Import 的实际步骤、验收身份与 ref 更新复核。
5. **导入与比对**：盘点原 task/ledger/runtime；核对 ID、版本、绑定、审批及熔断。冲突和缺失证据单独处理，禁止猜测并覆盖。
6. **分批切换**：停止新派发、处理在途 writer，执行可验证的单一真相切换；先小范围验证再扩大。
7. **恢复与负载验收**：模拟调度服务重启、worker 崩溃、重复交付、审批过期、容量竞争以及新旧投影读取。

数据比对可先采用只读导入演练；不能让两个后端同时拥有执行派发与状态修改权。

## 优点与代价

优点：启动交接、幂等身份、状态更新和容量管理有统一的持久操作模型，适合任务量、实例数和运维要求持续增长的系统。进程重启不依赖内存队列保持任务请求。

代价：增加常驻服务、事务存储及其运维；需要迁移状态与兼容读接口，回滚也涉及数据。新架构仍需实现正确的审批绑定、执行器复核和 writer 停止协议，不会自动修复这些业务规则。

相对工作量最大，适合明确准备投入任务队列、服务恢复和多实例能力的阶段。若只需处理当前单机多 worker 的九项遗漏，本方案的新增运维成本较高。若目标包含跨主机运行，还需单独确定事务存储与协调的部署能力。

## 迁移与回滚

- 切换前对原始文件和证据做只读备份，导入演练保留核对清单。
- 旧 JSON 兼容投影不能被旧入口再次写成权威状态。
- 回滚前停止新调度，确认在途 writer，导出切换后最新任务、命令、绑定、熔断与审批记录并验证旧版兼容性；不能恢复旧快照而遗失切换后的取消或审批。
- 证据无法还原的运行需要人工核对，不自动重做 author 或 promotion。

## 验收标准

九项行为回归全部通过；真实多进程容量约束有效；启动请求不会因服务重启丢失；过期持有者不能保存结果或推进 ref；同一提交不会因重复交付产生两个执行归属；取消及审批证据跨重启保持有效，变更过期的审批被拒绝。

兼容控制台读取和既有 V2 workflow 的相关/全量回归也必须通过。上线前还需要本方案新增的服务恢复与数据迁移验收，不能只沿用旧套件的通过结果。
